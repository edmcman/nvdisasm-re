# Decoding SASS from the machine descriptions

- Assembly (2026-10-15): `sass.assemble` inverts the FORMAT renderer and validates the selected class directly. ALTERNATE syntax may encode into canonical non-ALTERNATE forms; requiring the final decoder to select the input class rejects valid syntax. Inverse tables must match exactly, and overlapping fields must agree. Starred numeric fields such as `src_rel_sb=*7` are ignored for decoding but need their stated initialization during assembly. Controls/defaults come from the `$(...)$` groups, including scheduling/reuse tables. See [assembling.md](assembling.md).
- Native cubin probes (2026-10-15, CUDA 13.0.88): parameter bases are `0x160` on SM75/80/86/89, `0x210` on SM90, and `0x380` on SM100/103/110/120 (SM110 uses the SM101 md). The SM89 loader rejected an ELF readable by nvdisasm/cuobjdump until paired `.note.nv.tkinfo` and linked `.note.nv.cuinfo` were emitted. The writer identifies its tool as `sass-assemble`. SM107's cubin ABI remains unestablished independently of its supported raw encoding.
- SM90+ compatibility (2026-10-15): nvdisasm 13.4 requires `.nv.compat` for these ABI-v8 profiles, even with native `.text` and no `.nv.merc.*` intermediate sections. Its section type is `0x70000086`; the attribute stream describes the ISA class and Mercury major/minor version separately from per-kernel `.nv.info`. The native writer emits these records with opportunistic/fastpath finalization disabled.
- FORMAT-only operands (2026-10-15): SM100/101/103/120 `txq_urc_` prints `tid8` as an integer even though ENCODING has no source for it. The decoder renders an absent integer as zero. Assembly accepts only that zero value and rejects nonzero values rather than silently dropping a requested operand.

- `src/sass/md/parse.py` parses md classes/enums/tables; `src/sass/decode/ir.py` builds per-class decode IR; `src/sass/decode/pydecode.py` is a reference decoder; `python -m sass.check.pydecode_disasm ARCH real|synthetic|mutated [N]` diffs it against nvdisasm (`src/sass/oracle.py`, sqlite cache in `.cache/`; `src/sass/paths.py` locates the CUDA 13.4 nvdisasm). Real corpus = `.text.*` of cubins extracted by cuobjdump from `/usr/local/cuda/lib64` libs.
- Oracle: `nvdisasm -b SMxx raw.bin` decodes raw 128-bit words (~70k/s). One illegal word fails the batch (rc=1, empty stdout) but stderr lists every bad address; drop and rerun. Branch targets are absolute, so results depend on the word's address in the batch (recorded). Ambiguous encodings can abort with `nvdisasm fatal : More than one pattern matched ... at address` (also parsed). Some decodable words print as blank (JSON shows `opcode:""`): names like GATHER/SCATTER/`__HIR*`/PAUSE/E6M9 — cause not found, treated as status `blank`.
- Matching: opcode (`BITS_13_91_91_11_0`, ranges concatenated MSB first) + literal `=N` fields; `=*N` and unlisted bits are ignored. `=*X` operands (and the arguments of starred tables `=*T(a,b)`, which still decode) must hold a valid enum value or the class does not match (this separates classes sharing an opcode, e.g. NonZeroRegister vs ZeroRegister); plain `=X` operands out of their enum print `???N`. Tables decode by inverse lookup (first row wins; no row = illegal). Multi-field `ConstBankAddress2` stores offset/4, `IDENTICAL(a,b)` puts one field in both.
- ALTERNATE classes are assembler syntax and never printed, except pseudo classes whose `FORMAT_ALIAS` table (`GetPseudoOp*` in TABLES, `-` wildcard, first match) is non-zero and whose `$(...)$` scheduling operands are valid enum values (IMAD.MOV/SHL/IADD). md bug: GetPseudoOpRIR lists 32768 twice and lacks 65536, so 0x10000 is never SHL.
- md ambiguity: two non-ALTERNATE classes matching one word makes nvdisasm abort (`More than one pattern matched`, e.g. SM75 ald_PHYS_ vs ald__PATCH_*); pydecode treats it as illegal too.
- Tests: `uv run pytest -k pydecode` ratchets per-class pass/fail against `tests/baseline/SMxx.json` (`--update-baseline` to accept, `--full` for the whole real corpus). See `tests/README.md` for the other tests.
- Printing: for a value with several enum names the last *definition* wins (PT over P7, "64" over "_64", explicit `SR138=138` over the earlier `SR_CgaLinearMemorySlot`); defaults compared by value and omitted (`UImm(n/d*)` and `/PRINT` always print); `e_desc` (bit 101) off hides `desc[URx]`; floats `%.20e` if |x|>=1e9 else `%.20g`, `+INF`/`-QNAN`/`+SNAN`/`-0.0` with a trailing space (`+QNAN .H1`); a default operand that carries a modifier still prints (`[RZ.X8+UR4]`); flags `-|..|` wrap an operand plus directly following modifiers but not those after a `{/REUSE}` group; a `c[..][..]` bank followed by a modifier prints as `c[b] [o].MOD`; adjacent operands without a literal are space-separated (`RET.REL R2 -0x1240`).
