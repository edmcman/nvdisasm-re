# Testing notes

See `tests/README.md` for the Python, Ghidra and GPU tests, commands, options, caches, prerequisites, ratchets and how to write cases and GPU fixtures (never pytest-xdist).

- Caller-controlled input sampling (2026-10-21). `--sample 0..100` selects shared cases after generation and reference filtering; default 0 retains a stable representative for each available decoded class/modifier form, any additional backend-eligible representatives, and all `@retained` regressions and kernel/error/opaque cases. Intermediate percentages use versioned SHA-256 thresholds and are nested; 100 (also `--exhaustive`) includes the complete declared corpus. `Cases.sweep` now enumerates its full domain. Selection is local to manual families and generated planned forms, preserving shard independence; duplicate forms across the two sources may retain multiple representatives. Reference evidence uses 0%, preserving available form coverage while reducing case counts. GPU pass records include the percentage and sampling algorithm version; legacy records require actual revalidation rather than being relabelled. Retained cases always run in full, so retained corpora must stay small: keeping the SM100+ F2FP suites whole made them about 149,000 retained cases per language (exhaustive 256-code sweeps × modifier combinations × five operand-source classes), more than the rest of the language's shared cases at 0%. `@anchored` suites retain each sweep's edge indices on the all-register class (about 6,000 F2FP cases on SM100, 8,700 on SM107) and sample the rest, which records its reason in `sampled_reasons` (2026-10-21); and generated adapters select reference-backed input descriptions before encoding/decoding, avoiding construction of unselected instructions. IMAD immediate aliases and explicit memory adapters retain eager classification; selected deferred encodings are checked against their declared form/backend eligibility. Lightweight input/reference enumeration still runs for the full profile. Manual `c.add` cases were still encoded eagerly, which made F2FP's hand-written shard on SM100 take 35 s (66 of 100 profiled seconds encoding 148,876 cases to keep 6,996) and set each SM100+ language's evidence wall time; they now keep their fields and are encoded after selection (`Cases.encode_words`), identified by fields rather than words, with forms memoized per class and modifier fields (sampling version 3). The shard takes 9 s and SM100's exact evidence 13 s instead of 39; at 100% the 1,778,617 hand-written cases are identical to eager encoding.

- Generated shared cases (2026-10-17): supported ordinary integer forms are owned by `tests/autocases.py` and committed per-architecture plans. Named profiles in `tests/harness/autocase_profiles.py` preserve edge values and seeded random corpora; adapters place operands and calculate independent reference outputs at runtime. A retained manual regression supplements generation rather than excluding that form. `@retained(reason)` records why special-register, CX-header, p-code-cost or partial/opaque cases remain, and a test checks the supported manual cases have reasons. Operations without adapters remain manual. Missing architecture plans fail loudly, since silently skipping them would now lose migrated coverage. See `tests/README.md` for regeneration and validation.
- PR coverage comments (2026-10-16): CI compares committed `processor/SASS/semantics/coverage.json` at the PR event's base and head SHAs, independently of the generator freshness check. Same-repository PRs get a current bot comment with per-architecture opcode totals and changed class/modifier-combination status and verification counts; fork PRs and pushes skip commenting. Readable variants are omitted. Since 2026-10-17 the report leads with what changed: a red caution alert when GPU, ptxas or reference evidence falls (each opcode named once, at the strongest level that fell, with how to restore GPU passes), a warning when semantic coverage falls, and a per-architecture verification-change table; the opcode-coverage table is collapsed when no architecture's percentage moved. Every change is colored 🟢 better, 🔴 worse or ⚪ neutral, judging a level by its count together with the stronger levels, so a GPU pass demoted to reference is 🔴 for GPU and ⚪ for reference; more opaque or unverified counts are worse. Regressed opcodes sort first in each architecture's details. The PR carries a `coverage` label exactly while coverage differs from the base. When a newer report replaces the current comparison, CI posts it first, then edits previous reports into closed-by-default “Outdated coverage report” expansions with a superseded notice. Identical reports are not reposted, archived comments are ignored, and retries finish archiving without duplicating the latest report. Reverting all changes posts a no-change report, archives the previous summary, and removes the label, while an unchanged PR gets no initial comment. The `coverage-comment-report` artifact contains the full Markdown report when comment details exceed the size limit. Each report opens with the README's opcode-coverage badge, pinned to the PR head SHA so it shows the head's `badge.json` and links to its `coverage.html` (2026-10-17). The standard-library helper is `.github/scripts/coverage_comment.py`; its comparison and mocked API tests are `tests/test_coverage_comment.py`. Outside CI, `python3 .github/scripts/coverage_comment.py local [REV]` prints the same report comparing `REV` (default `HEAD`) with the working tree's `coverage.json`, without the badge or CI link (2026-10-19; the `sass-opcode-coverage` skill uses it for before/after).
- Shared hardware cases (2026-10-16): `tests/test_cases_on_gpu.py` executes exact-mode `emulator_cases` using native cubins, preserving operand bits, register aliases and reference outputs. `tests/harness/device_cases.py` batches scalar probes and isolates faults in bounded subprocesses; `device_setup.py` binds memory, lanes and runtime windows. Sampling originally followed `Cases.sweep`; the caller-controlled percentage policy below supersedes it. Unknown state is an error, and model-only cases report explicit reasons. `device_evidence.py` fingerprints complete passing families and executed cubins in `tests/baseline/gpu_case_passes.json`; `tests/evidence.py` credits the tested word directly as `cases/FAMILY`. Records never replace execution and become stale when inputs, expectations, sampler or generator/reference sources change. Existing whole-kernel fixtures and their evidence remain integration coverage. Probe-source digest (2026-10-17): the generator digest first hashed all of `src/sass`, `tests/refs` and the harness, so any semantics or reference edit (PR #30's new `tests/refs/integer.py` helpers) dropped every family's GPU evidence, FP included; it now hashes only the import closure of `device_cases`/`device_setup`/`device_runner` within `sass` and `tests` (no `sass.semantics` but `softfloat`, no `tests.cases`), whose inputs and expectations the signature already fixes. Records are all-or-nothing per family, so adding cases to a family still drops its evidence until a fresh GPU run.
- Sharded case consumers (2026-10-20). With fp32 at about 680,000 cases per language, every consumer that built a language's cases in one process became the bottleneck: `tests.evidence` (one worker per architecture, then SM89's `verified_words` rebuilding every family), `test_sweep_policy_and_all_cases_classified` (SM89 built sampled and exhaustive, serially: tens of minutes) and `test_retained_adapter_cases_have_reasons` (126 s). All now run `tests.harness.sharded.run` jobs, `shards=sharded.manual` where only the manual cases matter: at that time only manual sweeps depended on `--exhaustive`; the percentage policy below now applies to both sources. That required an order-free GPU signature (sum of per-scenario sha256 digests mod 2^256, `device_evidence.summary`), since strided shards don't preserve case order, so the records written before then went stale and needed a GPU re-run. `test_lifted_semantics` parametrizes from its results (one generation, not a tally pass and then an evaluation), and `test_pcode_semantics` from the saved plans' classes plus the manual cases.

- Verification evidence per class (2026-10-15) is derived from the tests by `tests/evidence.py` into `processor/SASS/semantics/evidence.json` (`uv run sass-refresh-coverage`; CI fails when it is stale) and shown in the coverage report. `reference`: emulator cases (`tests/cases`) name the class, checked against `tests/refs`. `ptxas`: an annotated `tests/ptx` probe (`// sass: MNEMONIC`) makes ptxas 13.0.88 emit the class; this is lowering evidence, not values. `gpu` (SM89 only): the class is on a GPU fixture kernel's data path, a static slice over md register reads/writes (`tests/harness/dataflow.py:expected`) in code order: the backward slice of the output stores' data, not following load/store address operands (`Ra*`, `memoryDescriptor`), plus the instructions in both the forward slice of the input loads (LDG) and the full backward slice. Stores of sliced values carry the slice through memory to later loads; a branch on a forward-sliced predicate counts. Address arithmetic is excluded; LDG/STG count for every fixture. Only fixtures that passed on the GPU exactly as committed count: `pytest -m gpu` records each passing fixture's fingerprint (kernel image, launch, inputs, reference outputs) and device in `tests/baseline/gpu_passes.json` and drops failing ones, so editing a fixture or its reference removes its G marks until the GPU tests run again (CI rebuilds the same cubins from the pinned CUDA 13.0.88 wheels, so it checks fingerprints without a GPU). Limits: straight-line code order (no CFG; the kernels are essentially straight-line) and one memory cell. Mnemonic matching of fixture `targets` credited 80 SM89 classes, including address arithmetic; the slice credits 119.
- Evidence and status per modifier value (2026-10-15). A class fixes only the operand form; its modifiers (FADD's `ftz`, `rnd`, `sat`; operand flags such as `Ra@negate`) are fields inside it. So class-level marks overclaimed: one FADD.RN fixture marked FADD "G" though FADD.FTZ.RZ never ran on hardware, and `f2fp_8b_upconvert__*` counted as native though only `dstfmt=F16` is modelled. `src/sass/sleigh/modifiers.py` defines a class's modifiers (the md modifiers but the scheduling hints, and each non-guard operand flag, `set`/`unset`, labelled by the first-defined enum member). A **form** is one combination of their values, decoded from an instruction word. `tests/evidence.py` records, per class, the forms each kind of evidence ran (`modifiers`: the column names; `forms`: {kind: [[label per modifier]]}), from the words themselves, independent of how the semantics branch. Full combinations are kept, so FTZ and RZ tested separately do not make FTZ+RZ tested. The generator writes each value's status into the manifests (`modifiers`: {modifier: {label: status}}), from the static rows `lower.enumerate_rows` produces: the status the admitting rows share, `partial` when some are opaque and some not (other modifiers decide; F2FP's `relu` is native only with `dstfmt=F16`), `primitive` when native and primitive rows mix. Values only illegal rows admit are left out, as are modifiers the encoding doesn't hold. The report marks a class `partial` when it has semantics but some of its values are opaque or partial (on SM89, 37 of F2FP's 42 classes with semantics; drawn half green, half red, and in the details as an "overall" chip coloured in proportion to its values), since the manifest's `native` only says some encoding is modelled. It also writes each class's `combinations`: {decides: [modifier], table: [[label..., status]], free: n}, the status of every combination of the modifiers that decide anything, each entry standing for `free` combinations of the rest; only legal combinations count: the md error conditions that read only modifiers are evaluated on each combination (`modifiers.conditions`), so F2FP's `srcfmt=F32` classes, which allow only `dstfmt` F16, E6M9 and BF16, no longer count 48 illegal TF32/E5M2/E4M3 combinations as opaque (on SM89 every F2FP class with semantics is then fully native). Each choice's chip status is derived from the same table (`modifiers.value_statuses`), and a choice no legal combination makes is left out. Labels are the enum member nvdisasm prints (`BF16`, not the first-defined `E8M7`). `modifiers.minimal` drops a modifier whose choices never change the status, so a uniform class is one entry (FADD's `fadd__RRR_RR`: native, 256 combinations) and `f2fp_merge_c__RCxR` is six (`dstfmt`, 16 each). Each cell shows C (classes) and M (modifier combinations, i.e. complete instruction forms; a class without modifiers counts as one) as full+partial/total, compacted (606k, 51.4M) with exact counts in the tooltip. A combination is verified only when a test ran exactly it: each tested form is looked up in its class's table. Evidence is counted once per class or value by its strongest kind, GPU, then ptxas, then reference (ptxas shows which PTX operation a class implements, a reference check only agreement with our own model); it is in the tooltips, the cards and the explanation box, not the cells. The evidence filter keeps rows with a matching cell and dims the others. A worked example (F2F on SM89, pinned to `f2f_f64_downconvert__RRR_RRR`: native except `.FTZ`, GPU-tested) heads the page; clicking a cell explains it the same way, rendered in the browser from the embedded detail. `coverage.html` is `src/sass/sleigh/report/index.html` with `report.css` and `report.js` inlined; Python only computes the data (the summary's per-opcode counts and the per-class detail), and the JavaScript renders the whole page from it, so the grid, cards, tooltips, example and explanations share one renderer and one set of numbers. The data is embedded as base64 gzip, inflated by the browser's `DecompressionStream`; `gzip.compress(mtime=0)` is byte-identical only for the same zlib (uv's Python 3.13 bundles 1.3.1, locally and in CI), which the CI diff of `coverage.html` relies on.

- `sass.ghidra_bridge` is the only path to `ghidra_emulate.py`/`ghidra_decode.py`; Ghidra tests run all selected languages concurrently, and `emulate_sharded` (`test_pcode_semantics`, `test_fixtures_emulated`) also splits each language's batch into chunks so up to 24 JVMs stay busy. `conftest.require_languages` fails on a stale `.sla` instead of letting concurrent Ghidra processes recompile it.
- In-process callers (no subprocess per batch) start the JVM themselves and use `ghidra_decode.describe` and `ghidra_emulate.session(ldefs, language)`, a request handler; kernel requests with `kernel.trace` also return each step's register writes for the first `kernel.trace_threads` threads. `launch.kernel_request` builds a whole-kernel request from `cubin.kernel_image` metadata.
- Launch constants (2026-10-15, nvcc 13.0 probe kernels each reading one of blockDim.x/y/z or using a local stack, per architecture): SM75-SM90 read blockDim from `c[0x0][0x0]`-`0x8` and the local stack base from `0x28`; SM100/SM103/SM110 (decoded as SM101)/SM120 use `0x360`-`0x368` and `0x37c`. `0x118` (SM80-SM89), `0x208` (SM90) and `0x358` (SM100+) hold the global memory descriptor; parameters start at `0x160`, `0x210` and `0x380`. SM107 has no nvcc 13 target, so it is not in `LAUNCH_LAYOUT`, and `kernel_request` refuses it rather than seed the wrong words. Since descriptors were modelled (2026-10-15), whole-kernel emulation of nvcc output gets through `desc[URx][Ra.64]` accesses: a scratch `out[i] = in[i] * 3 + blockDim.x` kernel gave the expected outputs on SM89, SM90, SM100 and SM120. The default descriptors stay 0 in bank 0. SM87's prologue needs BMOV barrier state from the environment.
- `sass-refresh-coverage` (and `sass.sleigh.build --generate-only`) rewrite every `.slaspec` even when the text is unchanged, and `require_languages` compares modification times, so afterwards every Ghidra test fails setup with "`.sla` is missing or stale" until `sass-build-languages` recompiles (1.5 minutes for all languages; the `.sla` bytes come out identical) (2026-10-21).
- Ghidra results are cached per request in `.cache/ghidra/` (2026-10-14), keyed by the language's `.sla`, specs and coverage manifest, every `src/sass` source and the Ghidra install; editing only tests reuses them. Since 2026-10-21 the key is the sources the program imports minus generator-only modules (`ghidra_bridge.GENERATORS`: families, operations, operands, lowering, build), which reach Ghidra only through the hashed `.sla`/manifest: measured over control/mufu/threads requests and samples of every family, the emulator loads 15 to 17 sass modules and no generator, and `test_ghidra_bridge` guards that. The key previously also missed `ghidra_decode.py`, which the emulator imports as a sibling script module. The launch layout (`sass.launch`: `LAUNCH_LAYOUT`, `WINDOWS`, `kernel_request`) lives outside `ghidra_bridge` because the GPU pass records' generator digest covers it: in the bridge package, every cache-code edit invalidated all GPU evidence.
- I2IP sub-byte forms (S2/U2 `.28`, S4/U4 `.24`) fill the high bits from C unshifted; only H1 selects C's high half (SM89 hardware, 2026-10-12; the earlier reference and p-code shifted for every non-H0 form).
- FLO.S32 (plain `FLO`; ptxas emits it for `bfind.s32`) searches the complement of a negative source: the highest bit differing from the sign, so -1 gives -1 like 0. FLO.U32 searches the value (SM89 hardware, 2026-10-12, fixtures `bfind_s32`/`bfind_shift_s32`; the earlier emitter and reference treated S32 like U32).
- Op-count samples (`synth.synthetic(..., legal=True)`) are md-legal words: up to 256 redraws use aligned low registers (UR0-UR63 on SM100+ are the only in-range uniform registers in 8-bit fields) or the zero register (HADD2.F32 requires `-RZ`).
- Operand flags (`Rc@negate`, `Sb@invert`) are not keys of `k.operand_types`; ask `tests.harness.case.flagged(k, name, flag)`, which reads them from the md format (2026-10-17). Five case checks spelled `"Rc@negate" in k.operand_types` were always false, so IDP's negated accumulator and the integer ALU's inverted sources had no cases until then; with them, all pass on SM89.

### Generated system and mixed-pair forms (2026-10-18)

The next 15-opcode batch adds FHADD2/FHMUL2/FHFMA2, S2R/CS2R/S2UR,
BRA/CALL/RET/EXIT/NOP, LDC/LDCU/ULDC and QSPC. Named profiles describe
finite mixed-lane inputs, constant bytes/banks/offsets, synthetic special
registers, control-flow predicates/displacements and mapped address ranges.
Expectations come from independent references. The mixed numerical helpers
are shared with the unchanged dense manual corpus in `tests/refs/mixed.py`.

Pure instructions retain the strict native p-code assertion. Constant loads
with ordering require exactly the `sass_memory_order` userop plus one event;
NOP requires an inspected zero-op body. Structured p-code bounds are emulator
assertions and do not change GPU expectations or hardware classification.
QSPC is classified as primitive in Python; its values are checked in Ghidra.

Ordinary constant-load and scalar control/register cases move to the profiles.
Manual aligned 64-bit constant pairs remain because their manifest forms are
partially native. Masked/cluster QSPC, missing-context failures, physical
branch/lane/CTA/query anchors, synchronization, kernel termination errors and
dense mixed floating-point corpora remain with explicit reasons.

- Remaining modeled-operation batch (2026-10-18): `autocase_remaining.py` adds independent memory and collective value profiles plus explicit synchronization environment contracts. Memory profiles cover signed loads, stores, register aliases, uniform/zero bases, offsets and shared strides; generic window boundaries and decoys remain manual. Warp profiles cover active masks, both predicate polarities, signed reductions and wide matches. Synchronization checks exercise the supplied environment response/event contract; they do not establish scheduler or barrier-state-machine correctness. MUFU still has no hardware-specific numerical model: its explicit failure contract is testable, but the planner reports a numerical-oracle gap rather than treating errors as value coverage. Generic memory's bounded p-code contract explicitly permits window-routing branches while still requiring exactly the named memory effects; ordinary pure-native and integer op-count guards stay strict.

- GPU memory harness (2026-10-18): `device_setup.memory_binding` sign-extends `Ra_offset` by the operand's own width (generic `LD` has a 32-bit offset, not 24) and adds the uniform register to the address for every `*_uniform` LD/ST/LDG/STG/LDL/STL/LDS/STS class, not only `ld_uniform`/`st_uniform`. A uniform pair is dropped from the case registers only when the wrapper rebinds it; shared LDS/STS keep the case's own UR value.
