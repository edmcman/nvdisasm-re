# SLEIGH generation (`src/sass/sleigh/`, `processor/SASS/`)

- Generation is deterministic: `pattern()` orders each pattern's conjuncts canonically (callers collect clauses from sets, so the order varied with the hash seed).
- `uv run sass-gen-sleigh SM89 ...` writes `processor/SASS/data/languages/sass_smXX.slaspec` + `sass.ldefs` (ids `SASS:LE:64:smXX`); `sass_common.sinc`, `.pspec`, `.cspec` are hand-written. Ghidra recompiles a stale `.sla` on load; `support/sleigh` compiles standalone (~5 s/arch).
- `src/sass/ghidra_bridge/ghidra_decode.py` (run with Ghidra's pyghidra venv) loads a language straight from the `.ldefs` via the package-private `SleighLanguageProvider(ResourceFile)` constructor (reflection) -- no install. `python -m sass.check.ghidra_disasm ARCH real|synthetic|mutated` diffs it against pydecode with `FLOAT_HEX` (SLEIGH can't print floats); guard shown as `@P0:` (SLEIGH drops the space before a mnemonic) and operand whitespace ignored.
- SLEIGH facts that shaped the generator: fields joined with `&` must be in one token, so every pattern is `(lo ; hi)` and patterns combine with `&`; subtable coverage is not folded into the parent's pattern (a subtable with no matching constructor makes the instruction fail, no fallback), so class discrimination is all in root constraints; overlaps are lenient (first in file order) unless nested; an operand may not be defined in several OR branches; a field can't be constrained and displayed in one pattern (separate aliases); `!=`/`<` on wide fields splits into huge state sets (16-bit `!=0` hung the compiler at 25 GB). Membership constraints now use aligned positive bit blocks. Pseudo-op scheduling validity uses a first-in-order blocker constructor.
- Ghidra silently truncates decompressed `.sla` data at 16 MiB (`SlaFormat.MAX_FILE_SIZE` / `LinkedByteBuffer.ingestStream`), causing random "Format violation" errors. Earlier large-OR failures were size failures. Shared display fields and per-class semantic span subtables keep all eighteen languages (nine architectures, exact and readable) under the cap (largest current build: SM90 exact, 16.03 MB with md CONDITIONS enforced for every class, 14.31 MB for family classes only; SM89 exact 12.81 MB, 2026-10-14). Enforcing every class's conditions naively made SM75-SM89 150-180 MB: one dead-end subtable per class decided on every combination of all its conditions' fields. Now each condition gets its own shared subtable, `P -> register rule` nests the register check under P's cubes (cubes(P) + cubes(register) constructors, not their product), and conditions branching on the same guard field share one table (SM120 17.3 -> 14.6 MB). Class span tables enumerate only output (and native/primitive) spans; read-only expression-sized inputs of opaque classes get per-operand subtables zero-extended to their widest view (SLEIGH requires one export size per subtable; >256 bytes uses `DYN_<operand>_<n>` registers). Enumerating all spans jointly made TEX tables 432 rows.
- A subtable's common sub-pattern folds into the referencing constructor, so a word failing it does not fail that constructor: it falls back to a less specific sibling. `Gen.decision`'s catch-all shortcut therefore needs siblings without subtables: with them, TEX/TLD .SCR words over the 4-coordinate limit fell through `(lodlc=5) & ok1` to the catch-all and decoded (2026-10-14, seen once every class's conditions were checked). Dead-end tables are safe: their inner tables (catch-all plus cubes, `never`'s two one-bit constructors) have no common pattern.
- Ghidra caches instruction prototypes by a 32-bit CRC of the constructor tree and trusts the hash entirely (`SleighLanguage.parse` `instructProtoMap`, `SleighInstructionPrototype.equals`). SASS languages have so many distinct trees that one process decoding ~64k varied words hits about one collision per architecture: the word reuses another class's prototype (e.g. LEA shown as HMUL2), though it decodes correctly alone. Real Ghidra sessions are exposed too (worth reporting upstream). `sass-compare-ghidra` re-decodes mismatches in a fresh process and labels those `collision`.
- Uniform zero depends on the architecture and the field width. SM75-SM90 define URZ=63. SM100+ define URZ=255 and treat UR63 as an ordinary register, but six-bit fields still encode URZ as 63. `Gen.register_zero` derives the zero from the md, and URZ gets its own register slot outside the 64-register bank.
- Register dataflow p-code: md register reads/writes via opaque pcodeops, instruction guards, and branch/call/return. Modifier spans are evaluated by `src/sass/md/expression.py`, exactly (including 0, 3, and matrix spans above 8), without a widest-span fallback. Immediate operands with misleading latency resources (IPA `attr`) are excluded by operand type. Register-bank overflow uses sinks to preserve display decoding; its dataflow is undefined. Wide zero constants use `zext`; above SLEIGH's 256-byte temporary cap, initialized internal ZERO registers are used.
- `SASS_SLEIGH_OUT=/tmp/...` redirects generation and Ghidra tests; copy the shared `.sinc`, `.pspec`, and `.cspec` there first. `tests/test_pcode_dataflow.py` (`tests/harness/dataflow.py`) compares structured Ghidra p-code against decoded md operand roles/spans. `sass-compare-ghidra` compares standalone 64-bit immediates in MOV.64/UMOV.64/MOV64IUR modulo 2^64 because SLEIGH prints computed values as signed int64.
