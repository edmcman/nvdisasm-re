**GPU (2026-10-20):** the complete fp32 family passed on SM89 (NVIDIA GeForce RTX 4070 Laptop GPU, CUDA driver API 13.0): all 580,088 shared-case scenarios and 106 GPU tests passed (`nice uv run pytest -m gpu --require-gpu --family fp32`, sampled mode, 26.5 minutes). The new `baseline/gpu_case_passes.json` fp32 entry replaces the pass that the expanded case signature invalidated. SM89 class evidence moves from 532 GPU / 110 reference to 568 GPU / 74 reference in both lowerings, and GPU combination counts for FADD, FCHK, FFMA, FMNMX, FMUL, FSEL, FSET and FSETP now exceed their pre-change values (FCHK 68 and FSEL 272 are restored exactly). Eight FMUL combinations remain reference-only.

**FMZ and XORSIGN (second 2026-10-20 step).** SM89 probes (`research/fmz_xorsign/probe.py`, 34,413 observations, no mismatches) established both remaining rules (`docs/hardware-facts.md`). `.FMZ`: a factor with a zero exponent (zero or subnormal) makes the product +0, even against Inf or NaN; FFMA then adds Rc with FTZ, rounding and SAT. FMNMX.XORSIGN with `|x|`/`-x`: the modified operands are compared and the result's sign is the XOR of the encoded signs. New references (`refs.float.fmz`, `fmnmx_xorsign(encoded=)`) replace the two adapter blocks, which moves every blocked form in the table above into the plans (7,648-8,192 per architecture before SM100, 4,096 after). FMUL/FFMA/UFMUL/UFFMA `.FMZ` became native in the exact lowering (previously a runtime primitive), including SM120's 1,888 uniform forms, which have reference evidence only; the existing XORSIGN semantics already matched. A dense FMZ zero/Inf/NaN factor corpus stays manual. The complete fp32 family (679,576 scenarios) passed on SM89, so every SM89 FMUL, FFMA and FMNMX combination now has GPU evidence.

FTZ and FMZ share one body (`Instruction.select_in`): with a body per label SM90 exact compiled to 16,848,482 bytes, over Ghidra 12.1's 16 MiB limit; shared, it is 16,601,730. Plain forms are unchanged, but FTZ forms execute 21-35 more p-code operations (`ffma__RRR_RRR` 48 -> 83; reviewed op-count baselines accepted), recorded with its causes and fixes in `docs/open.md`.

Case streaming: the larger fp32 family made `test_lifted_semantics` hold every language's cases in pytest and fork 32 workers from it, and the OOM killer stopped it with the desktop session. Both semantics tests now generate, judge and discard shards inside `forkserver` workers (`tests/harness/sharded.py`); fp32 on all 20 languages takes 17.5 minutes and 14 GiB (lifted) and 38.5 minutes and 25.9 GiB (Ghidra), and the streamed shards yield exactly the old per-class case counts.

Arithmetic keeps the existing undefined-NaN-payload and documented Ghidra RN-underflow exclusions.

**Testing/environment:** initial SM120 Ghidra attempts hit a SQLite WAL cache lock in the temporary parallel runner. The first GPU attempt failed during setup in a workspace without `libcuda.so.1` or NVIDIA device nodes; the fp32 family was then run on an SM89 device and passed (see **GPU** above).

Reproduce with the repository development environment (all builds/tests under `nice`; language compilation and hardware checks outside the sandbox):

```sh
export PYTHON_CPU_COUNT=1
nice uv run pytest tests/test_assemble.py tests/test_refs.py tests/test_extended_autocases.py tests/test_evidence.py
nice uv run sass-build-languages --generate-only --coverage
for arch in SM75 SM80 SM86 SM89 SM90 SM100 SM101 SM103 SM107 SM120; do
  nice uv run python -m tests.autocases "$arch" --write
  for fp in exact readable; do
    nice uv run pytest tests/test_lifted_semantics.py tests/test_family_lowering.py --family fp32 --arch "$arch" --fp "$fp"
  done
done
nice uv run sass-build-languages
for arch in SM75 SM80 SM86 SM89 SM90 SM100 SM101 SM103 SM107 SM120; do
  for fp in exact readable; do
    nice uv run pytest tests/test_pcode_semantics.py -m ghidra --family fp32 --arch "$arch" --fp "$fp"
  done
done
nice uv run pytest -m gpu --require-gpu --family fp32
nice uv run sass-refresh-coverage
python3 .github/scripts/coverage_comment.py local 5d8f17bac1439bc3b7a811d3dfc007e32abaf481
```

In this 2-core/8-GiB workspace, architecture/lowering runs were split into individual processes and coverage refresh was staged into manifest generation, per-architecture evidence collection, and the standard coverage writer. All generated coverage artifacts use the canonical generator and renderer.
