# nvdisasm reverse engineering

Target: `nvdisasm` from CUDA 13.4 (V13.4.92, built 2026-09-01), stripped x86-64 PIE.
Local copy used so far: `/tmp/.venv/lib/python3.13/site-packages/nvidia/cu13/bin/nvdisasm`.
All addresses below are specific to that build.

## Tooling
- Ghidra via GhidraMCP. GUI server was at `http://127.0.0.1:33363/` (`set_ghidra_server`). Image base 0x100000, so Ghidra addr = file/objdump addr + 0x100000.
- GhidraMCP lookups need exact function entry addresses; inner addresses return "No function".
- `uv run extract_md.py <nvdisasm>` dumps the embedded machine descriptions to `out/raw/` (gitignored, monolithic). `python3 build_out.py` lays them out as `out/SMxx/{latencies,patterns}.txt`, `out/SMxx/md/{_NN_SECTION,OPCODE}.txt` and `out/SMxx/semantics/OPCODE.json` (committed).

## Findings
- Opcode/operand name strings are ROT13 (`rot13_decode` 0x168cb0); `strings` won't find them. Mnemonics are matched by prefix (`str_after_prefix` 0x11831b).
- Diagnostics: `diag_report` 0x111b70 (variadic). Messages are 16-byte `diag_msg {severity, suppressed, fmt}` records reached via a pointer slot: code -> slot -> record -> fmt.
- Branch-stack pass (pre-Volta SSY/PBK/PCNT/PRET/... stack), driver `bstack_analyze_function` 0x1da320: entry frame per block, one ordered pass over CFG edges (`bstack_propagate_edge`), then join/exit checks and pop-target resolution (`resolve_branch_target` 0x1d11b0, emits `TARGET=` annotations). Push/pop kind pairs: 1 RET/PRET, 2 SYNC/SSY, 3 BRK/PBK, 4 CONT/PCNT, 5 LONGJMP/PLONGJMP, 7 EXIT/PEXIT.
- Machine descriptions: per arch (SM75 80 86 89 90 100 101 103 107 120) three blobs in `.data` — md, latencies, patterns — registered by `md_register_embedded_blob` 0x1be200, loaded by `md_load_blob` 0x1beb30.
  - Cipher `mdcipher_decrypt` 0x173030: glibc-LCG keystream (4 bytes/step) + inverse sbox at 0x1fa5e0, ciphertext-chained, seeded by a 16-bit per-arch key.
  - md blobs are then LZ4 stream-compressed chunks `{u32 raw, u32 comp, data}` with 64 KB dictionary; latencies/patterns are encrypted only.
  - SM107 also has its own md/latencies/patterns (registered at 0xbde60, just past the other nine; `extract_md.py` missed it until 2026-10-13).
  - `-b` accepts more names than there are mds: `arch_family_name` 0x1bb0c0 maps the SM number to the md name passed to `md_load_blob`. SM87/SM88 -> SM86, SM110 -> SM101 (CUDA 13 renamed Thor sm_101 to sm_110), SM121 -> SM120; `a`/`f` suffixes are ignored. Verified by identical nvdisasm output on synthetic words, so the aliases need no separate tables or languages.
  - External override files `md_SMxx` / `latencies_SMxx` / `patterns_SMxx` are supported (`md_register_override_file` 0x1be3f0); a `_` suffix means key 0 (plaintext) — untested.
- Semantics model: md gives per-CLASS FORMAT (operand names), CONDITIONS, PROPERTIES (INSTRUCTION_TYPE...), PREDICATES (IDEST_SIZE/ISRC_*_SIZE in bits), OPCODES, ENCODING. latencies gives connectors (Ra/Rb/Rc/Re read, Rd/Rd2 written; URx, Px analogues), TABLE_TRUE/OUTPUT/ANTI latencies and OPERATION SETS (pipes). Register span = ceil(SIZE/32). No functional (value) semantics exist.

## Decoding (sass/, tests/)
- `mdlib.py` parses md classes/enums/tables; `sass/ir.py` builds per-class decode IR; `sass/pydecode.py` is a reference decoder; `python -m tests.compare_pydecode_disassembly ARCH real|synthetic|mutated [N]` diffs it against nvdisasm (`tests/oracle.py`, sqlite cache in `.cache/`; `tests/paths.py` locates the CUDA 13.4 nvdisasm). Real corpus = `.text.*` of cubins extracted by cuobjdump from `/usr/local/cuda/lib64` libs.
- Oracle: `nvdisasm -b SMxx raw.bin` decodes raw 128-bit words (~70k/s). One illegal word fails the batch (rc=1, empty stdout) but stderr lists every bad address; drop and rerun. Branch targets are absolute, so results depend on the word's address in the batch (recorded). Ambiguous encodings can abort with `nvdisasm fatal : More than one pattern matched ... at address` (also parsed). Some decodable words print as blank (JSON shows `opcode:""`): names like GATHER/SCATTER/`__HIR*`/PAUSE/E6M9 — cause not found, treated as status `blank`.
- Matching: opcode (`BITS_13_91_91_11_0`, ranges concatenated MSB first) + literal `=N` fields; `=*N` and unlisted bits are ignored. `=*X` operands (and the arguments of starred tables `=*T(a,b)`, which still decode) must hold a valid enum value or the class does not match (this separates classes sharing an opcode, e.g. NonZeroRegister vs ZeroRegister); plain `=X` operands out of their enum print `???N`. Tables decode by inverse lookup (first row wins; no row = illegal). Multi-field `ConstBankAddress2` stores offset/4, `IDENTICAL(a,b)` puts one field in both.
- ALTERNATE classes are assembler syntax and never printed, except pseudo classes whose `FORMAT_ALIAS` table (`GetPseudoOp*` in TABLES, `-` wildcard, first match) is non-zero and whose `$(...)$` scheduling operands are valid enum values (IMAD.MOV/SHL/IADD). md bug: GetPseudoOpRIR lists 32768 twice and lacks 65536, so 0x10000 is never SHL.
- md ambiguity: two non-ALTERNATE classes matching one word makes nvdisasm abort (`More than one pattern matched`, e.g. SM75 ald_PHYS_ vs ald__PATCH_*); pydecode treats it as illegal too.
- Tests: `uv run --with pytest python -m pytest tests -k pydecode` ratchets per-class pass/fail against `tests/baseline/SMxx.json` (`--update-baseline` to accept, `--full` for the whole real corpus). See Tests below for the other layers.
- Printing: for a value with several enum names the last *definition* wins (PT over P7, "64" over "_64", explicit `SR138=138` over the earlier `SR_CgaLinearMemorySlot`); defaults compared by value and omitted (`UImm(n/d*)` and `/PRINT` always print); `e_desc` (bit 101) off hides `desc[URx]`; floats `%.20e` if |x|>=1e9 else `%.20g`, `+INF`/`-QNAN`/`+SNAN`/`-0.0` with a trailing space (`+QNAN .H1`); a default operand that carries a modifier still prints (`[RZ.X8+UR4]`); flags `-|..|` wrap an operand plus directly following modifiers but not those after a `{/REUSE}` group; a `c[..][..]` bank followed by a modifier prints as `c[b] [o].MOD`; adjacent operands without a literal are space-separated (`RET.REL R2 -0x1240`).

## SLEIGH (processor/SASS, sass/gen_sleigh.py)
- `python3 -m sass.gen_sleigh SM89 ...` writes `processor/SASS/data/languages/sass_smXX.slaspec` + `sass.ldefs` (ids `SASS:LE:64:smXX`); `sass_common.sinc`, `.pspec`, `.cspec` are hand-written. Ghidra recompiles a stale `.sla` on load; `support/sleigh` compiles standalone (~5 s/arch).
- `tests/ghidra_decode.py` (run with Ghidra's pyghidra venv) loads a language straight from the `.ldefs` via the package-private `SleighLanguageProvider(ResourceFile)` constructor (reflection) -- no install. `python -m tests.compare_ghidra_disassembly ARCH real|synthetic|mutated` diffs it against pydecode with `FLOAT_HEX` (SLEIGH can't print floats); guard shown as `@P0:` (SLEIGH drops the space before a mnemonic) and operand whitespace ignored.
- Don't name a repo dir `ghidra/`: from the repo root Python treats it as a namespace package shadowing pyghidra's Java `ghidra` package (RecursionError).
- SLEIGH facts that shaped the generator: fields joined with `&` must be in one token, so every pattern is `(lo ; hi)` and patterns combine with `&`; subtable coverage is not folded into the parent's pattern (a subtable with no matching constructor makes the instruction fail, no fallback), so class discrimination is all in root constraints; overlaps are lenient (first in file order) unless nested; an operand may not be defined in several OR branches; a field can't be constrained and displayed in one pattern (separate aliases); `!=`/`<` on wide fields splits into huge state sets (16-bit `!=0` hung the compiler at 25 GB). Membership constraints now use aligned positive bit blocks. Pseudo-op scheduling validity uses a first-in-order blocker constructor.
- Ghidra silently truncates decompressed `.sla` data at 16 MiB (`SlaFormat.MAX_FILE_SIZE` / `LinkedByteBuffer.ingestStream`), causing random "Format violation" errors. Earlier large-OR failures were size failures. Shared display fields and per-class semantic span subtables keep all eighteen languages (nine architectures, exact and readable) under the cap (largest current build: SM90 exact, 12,179,148 bytes). Class span tables enumerate only output (and native/primitive) spans; read-only expression-sized inputs of opaque classes get per-operand subtables zero-extended to their widest view (SLEIGH requires one export size per subtable; >256 bytes uses `DYN_<operand>_<n>` registers). Enumerating all spans jointly made TEX tables 432 rows.
- SLEIGH compiler memory: compiling the SM100+ languages took 10-12 GiB of Java heap each, and `build_languages` once ran all 18 compilers at once (no `MAXMEM` in `support/sleigh`, so each JVM may take a quarter of RAM); eight together exhausted 93 GiB and systemd-oomd killed whole terminals (2026-10-13). `build_languages` now runs `MemAvailable // 16 GiB` compilers with `-Xmx16g` (`COMPILER_HEAP`). The test layers are small by comparison (one emulation JVM ~0.7 GB on SM90).
- Ghidra caches instruction prototypes by a 32-bit CRC of the constructor tree and trusts the hash entirely (`SleighLanguage.parse` `instructProtoMap`, `SleighInstructionPrototype.equals`). SASS languages have so many distinct trees that one process decoding ~64k varied words hits about one collision per architecture: the word reuses another class's prototype (e.g. LEA shown as HMUL2), though it decodes correctly alone. Real Ghidra sessions are exposed too (worth reporting upstream). `compare_ghidra_disassembly` re-decodes mismatches in a fresh process and labels those `collision`.
- Uniform zero depends on the architecture and the field width. SM75-SM90 define URZ=63. SM100+ define URZ=255 and treat UR63 as an ordinary register, but six-bit fields still encode URZ as 63. `Gen.register_zero` derives the zero from the md, and URZ gets its own register slot outside the 64-register bank.
- Register dataflow p-code: md register reads/writes via opaque pcodeops, instruction guards, and branch/call/return. Modifier spans are evaluated by `sass/mdexpr.py`, exactly (including 0, 3, and matrix spans above 8), without a widest-span fallback. Immediate operands with misleading latency resources (IPA `attr`) are excluded by operand type. Register-bank overflow uses sinks to preserve display decoding; its dataflow is undefined. Wide zero constants use `zext`; above SLEIGH's 256-byte temporary cap, initialized internal ZERO registers are used.
- `SASS_SLEIGH_OUT=/tmp/...` redirects generation and Ghidra tests; copy the shared `.sinc`, `.pspec`, and `.cspec` there first. `tests/test_pcode_dataflow.py` (`tests/harness/dataflow.py`) compares structured Ghidra p-code against decoded md operand roles/spans. `compare_ghidra_disassembly` compares standalone 64-bit immediates in MOV.64/UMOV.64/MOV64IUR modulo 2^64 because SLEIGH prints computed values as signed int64.

## Open
- Cooperative scheduling covers one interleaving: round-robin lockstep keeps warps in step, so `shared_exchange` likely passes even with BAR.SYNC as a no-op. Run cooperative kernels under adversarial schedules (warp-greedy until blocked, reverse, seeded random) and require identical results: that tests barrier enforcement and that fixture kernels are race-free. Timing proper matters only for racy code, fence-based ordering (memory model, not cycles) and scoreboards: the emulator completes instructions instantly, trusting control bits, and GPU fixtures keep the original controls on patched words, so a patched slot with longer or variable latency could read stale values on the GPU.
- Trace the `-plr` liveness code that consumes connectors (start at the "Cannot %s as flow analysis is disabled" check, Ghidra 0x10a327).
- Parse md + latencies into a per-opcode table (operands, role, width, pipe, latency).
- Why nvdisasm prints some decodable instructions blank (GATHER, SCATTER, `__HIR*`, BPT.PAUSE, E6M9 immediates, SM75 HMMA .BF16/.TF32) and silently drops some modifier values (SM75 HMMA `altfmt=INVALID3`). Not a name table in the binary; never seen in real code.
- SLEIGH generation from `sass/ir.py` (plan phase 3).
- Semantics roadmap, ordered by `tools/semantic_census.py` (2026-10-08; share = average fraction of all real-corpus instructions across SM75-SM120). After the control-flow fix: native 58-76% per arch, opaque 16-36%, primitive 6-8%.
  1. Done: control flow on every fallback branch; native SM90+ BRA.
  2. Done: cheap coverage (~10%): `URb`/`URc` operand names in IMAD/ISETP/IADD3/LEA emitters (~3.5%, ~7% on SM90); alias uniform/variant ops to existing emitters (UIADD3, UIMAD, USHF, ULEA, UISETP, ULOP3, USEL, UMOV, VIADD, IADD; ~3.5%); native PRMT (1.6%); FSEL (1.1%), FMNMX (0.6%, NaN/±0 rules).
  3. Done: native RN fp64 DFMA/DADD/DMUL and ordered/unordered DSETP (~5%); DFMA via Ghidra's 16-byte float, where the double product is exact. Directed rounding and DSETP MIN/MAX stay opaque.
  4. Done: native packed fp16x2 HADD2/HFMA2 (~2%) with lane broadcasts/modifiers and SAT, including the `HFMA2.MMA Rd, -RZ, RZ, imm` constant move. FTZ/FMZ, alternate formats, RELU and other MMA forms stay opaque.
  5. Done: carry chains IADD3.X, LEA.HI.X, IMAD.X and ordinary predicate outputs (SM89 hardware-established; all-architecture emulator/dataflow checks).
  6. Kernel parameters as named constant-bank-0 variables in the decompiler (offsets/sizes from `.nv.info`, `sass/cubin.py`).
  Stays primitive: SHFL, VOTE, BAR, BSSY/BSYNC, MUFU (multi-thread or hardware approximation). Ghidra's emulator FloatFormat underflow bug (see below) could be reported upstream.

## Semantics families (sass/families/, 2026-10-12)
- Families are Python functions over the md-decoded instruction (`@family('IMAD', 'UIMAD')`, `sass/sem_family.py`), returning `outputs(Rd=..., Pu=...)` of `sass.sem` bitvector expressions (widths in bits, `extract`/`concat`). One definition serves `sass.sem_lift.lift` (Ghidra-free semantics, evaluated by `sem_eval`) and the SLEIGH backend `sass/sem_sleigh.py`; `operations.emit` uses a family when one covers the class. Integer families are migrated (`sass/families/integer.py`), the FP32/FP64/packed-half floating families (`sass/families/floating.py`), F2I/F2IP (`sass/families/f2i.py`) and every F2FP form except stochastic rounding (`f2fp_rs*`, opaque) (`sass/families/f2fp.py`).
- Static answers (selectors `i.select_fork`, one family body per label, modifier bits `i.operand_*`, `i.is_zero`, `i.has_operand`, `i.select_lookup_const` label->number tables, `i.static` for immediates of at most 8 bits) are Python values that SLEIGH enumerates; operand values are expressions. `a if c else b`, `and`/`or`/`not` are rewritten so they work on both.
- A family that never asks about a selector, modifier bit or defaulted numeric operand models only its md default: any other value is unmodelled (opaque). Selectors without an md default (`/ONLY64:size`, `/XORONLY:xor`) must be asked. `i.ignore(name)` marks an operand irrelevant to an encoding (ISETP's Pr without .EX). Operands with bracketed parts (C, CX, A, DESC) are values, not selectors, even where the type names an md enum.
- md CONDITIONS are enforced in SLEIGH for family classes (except conditions on scheduling hints alone); `tests/compare_ghidra_disassembly` expects those words rejected.
- The md's `PR` operand (P2R/R2P) is a 7-bit value, P0 the low bit. `Predicate_vimnmx` (VIMNMX.pred, P0-P6, no PT) is a P-file register type; its Pu/Pv semantics are unknown (opaque).
- UPRMT is PRMT's IDX mode (`/IDXOnly("IDX"):idx`). Constant-bank widths come from md ISRC_<slot>_SIZE (IMAD c[][] is 64-bit on SM86+).
- F2FP on `sass/fpformat.py`: values are exact `Parts` (sign, sig, lsb, top), `round_parts` rounds once into any `Dest` (`general=True` for scaled parts: an exact left shift where no rounding is needed), `widen` is exact, and UE8M0 scales are exponent offsets (`Parts.scaled`), not float multiplies. Exhaustive checks against `tests/refs/fpformat.py`: 0 mismatches. Scaled upconverts model only `iswzC=H0` (scales Rc[15:0], low lane low byte): ptxas puts the PTX scale pair there independent of `extract_B` and never emits H1/B0-B3 (`research/semantics-migration/f2fp_scaled_ptx.md`; the earlier emitter took the scales from the `extract_B` half). SM86-SM90 UF2FP name formats as one `dfmt.sfmt` selector; `uf2fp_merge_c__URURI` (immediate C, no `extract`) stays opaque. `widen` is static per format (re-bias normals; subnormals shift onto dst's grid or, where dst makes them normal, take one constant-shift code per leading bit), and unscaled upconverts choose each format's whole widening at decode time. F2I accepts .FTZ (toward zero every |x| < 1 gives 0, so FTZ cannot change the result) and falls back to its primitive; F2IP with C `.H1` (`extract`) is opaque (the earlier emitter ignored it and kept C[15:0]).
- Control flow (`sass/families/control.py`, Phase 6a): `outputs(flow=goto|call|ret(target, cond))`; `i.branch_target(name)` is a direct target (SLEIGH: the branch-target subtable, `goto`/`call` without brackets; lift: the absolute address, RSImm relative to the next instruction), other targets are values (`call [x]`, `return [x]`). Flow travels through row merging as pseudo-outputs (`__flow_target`/`__flow_cond`). `sem_eval.execute` sets `State.pc`, so the lifted tests check `__counter`. Modelled: BRA (not .DIV/.CONV, uniform target/predicate), EXIT (.NO_ATEXIT too), CALL.NOINC (absolute/relative immediate, c[][] and absolute register targets; the earlier emitter treated relative offsets as absolute), RET.ABS/REL.NODEC, NOP.
- Memory and special registers (`sass/families/memory.py`, Phase 6b): `outputs(stores=[store(space, addr, value)], effects=[effect(name, args...)])`; stores and effects merge as pseudo-outputs (a store's width follows sz, so `Merger.bodies` splits rows whose output widths differ). `i.encoding(name)` passes a selector's raw value (the memory-ordering controls `sass_memory_order` validates); `i.special(name, w)` reads the special register a SpecialRegister field selects (SRZ 0). LDG/STG/LDS/STS/LDL/STL/LDC, ULDC c[][] and S2R/CS2R/S2UR are families (uniform address parts `Ra_URb`/`Ra_URc` add to the address); dual registers, explicit descriptors, predicate results, non-IA modes and SM75 `.ZD` (no default, meaning unknown; the earlier emitter ignored it) stay opaque.
- md CONDITIONS that read a span field (sz, e: register range/alignment rules such as "sz=64 -> Rd even") are checked per span variant (`Gen.conditions(k, domain)`, `span_variants(domains=True)`), with the span fields narrowed to the variant's values, not in the root pattern: at the root they multiplied the global decision tree (SM89 10 -> 76 MB with the memory families).
- Runtime-executed encodings (Phase 6c): a family raises `primitive()` (`sass_prim_*` behind the same selector guards; lift status `primitive`, value checks left to the emulator tests). `i.static_low(name, bits)` asks only the low bits of a wide immediate (UP2UR's 7-bit predicate mask; SLEIGH constrains a sub-field); fixed registers (`sem.reg('UP', k, 1, element=1)`) lower to their names.
- Conversions (`sass/families/convert.py`, 2026-10-13): FRND (F32/F64), I2F/I2FP (8/16/32/64-bit sources with bsel/hsel, F16/BF16/F32/F64 destinations), F2F (F16/F32/F64) and F2I (F16/BF16/F32/F64 to S/U 32/64) are exact in every rounding mode on `fpformat` (`int_parts`, 64-bit `round_parts`; `arith` picks W=64 for F64). Rounding modes, destination formats, signedness and NTZ are decode-time lookups (`fpformat.chosen_rounding`, shared with F2FP; `fpformat.round_up` is the one round-up rule): forking per label made SM86 exceed 16 MiB. F2F/F2I/I2F/FRND with a half/byte source read only that slice (layer 3 `part_selector`). PLOP3/UPLOP3 (`integer.py`): Pu's truth table is enumerated, Pv looks its bit up (`vimm8 >> (4p+2q+r)`; enumerating both was 65536 rows); register-source classes stay opaque. FCHK (`floating.py`), R2UR (Pu=PT only), RET.REL (next + Ra + offset) are native; BMOV/BREAK/WARPSYNC are runtime primitives (`families/runtime.py`) (B0-B15 are not in the register model yet).
- `i.select_lookup(name, {label: expr})` returns the value a selector chooses as one decode-time choice instead of branching the family per label (FSETP's comparison, shared by Pu and Pv); `i.select_lookup_const` is its constant case. In SLEIGH, operand modifier bits (|x|, -x, ~x, !P) are likewise decode-time choices of the operand value, except on loaded operands (c[], cx[]), whose load each table would repeat. Both keep the enumeration small (FFMA has 6 modifier bits).
- Floating point in the IR: `fadd`/`fmul`/`ffma` (rounding mode, FMUL's 2^k scale), `flt`/`fle`/`feq`/`fnan`, `fconv`, exactly rounded (`sass.softfloat`) in `lift`/`sem_eval`. The SLEIGH lowering keeps the earlier strategies (RN at native width, FFMA/scaling via the doubled format, directed modes via TwoSum residual and a 1-ulp step); the readable language uses the plain formula, and families write readable FFMA/scaled FMUL as their unfused operations. FTZ (branch-free), SAT and min/max NaN/zero rules are family IR (`sass/families/floating.py`).
- SLEIGH backend: the rows of static answers are merged by anti-unification (one key at a time, default rows, rows the default reproduces absorbed, choices reused across outputs); outputs merge jointly, so a decode-time choice can select whole bodies (one constructor computes a shared constant load once). Cost = .sla size + 8 x executed operations. A subtable exporting a register exports the register itself: later outputs are captured before the first write.

## Operand values and instruction semantics (2026-10-07)
- `sass/semantic.py` preserves exact register effects for all classes, and materializes typed immediate/table/modifier/constant-bank values for supported operations. CX/descriptors/attribute/stateful operands require an explicit `sass_operand_value` provider.
- Every opcode with semantics is a family (`sass/families/`, Phase 6c, 2026-10-13); `sass/operations.py` only routes a class to its family and `dispatch`es the native body behind decode-time selector patterns, with the opaque call or the family's runtime primitive (`fallback='prim'`, or `primitive()` rows such as QSPC and the warp/synchronization/MUFU family in `sass/families/runtime.py`) for the rest. Unknown conventions remain opaque: ISETP.EX, SM120 extra IMNMX predicates, descriptor/extended memory, branch-stack CALL/RET depth changes.
- FADD/FMUL/FFMA/FSETP are native p-code with .FTZ/.SAT/FMUL scale; only .FMZ uses `sass_prim_*` (`dispatch(b,'prim')`). RN FFMA is `float2float(fp64 a*b + c)`: double rounding, rare 1-ulp differences. Ghidra 12.1.4's emulator rounds results in (2^-150, 2^-149) to zero instead of 2^-149 (`FloatFormat.getEncoding` `n < 0` branch); tests exclude that band.
- `sass/runtime.py` (test-only; Ghidra never loads it) supplies strict CPU primitives; `sass/softfloat.py` uses exact rational IEEE rounding. MUFU requires a hardware-specific handler. Warp operations use explicit 32-lane context (cooperative kernels gather it per instruction); synchronization events require acknowledgement and do not implement a scheduler. Barrier reductions require a handler.
- Special registers are a register file at offset 0x3000 named from the md `SpecialRegister` enum (`SR_CTAID.X`; `_64` views for CS2R.64); S2R/CS2R are plain copies and SRZ reads 0. Emulation seeds them by name like any register; unseeded ones read 0.
- Spaces: `ram`, `cbank` (bank << 32 | uint32(offset)), `shared`, `localmem`. The identifier `local` is reserved in SLEIGH. The Phase 5 test harness reads parameter offsets from cubin PARAM_CBANK/KPARAM_INFO records; these SM89 pointer kernels use bank 0 base 0x160. The general loader/compiler prototype remains Phase 6 work.
- Detailed per-class coverage manifests are generated beside each `.sla`; committed `processor/SASS/semantics/coverage.json` summarizes all architectures. Native status records a candidate override with selector guards, not all-encoding coverage.
- Architecture support and hardware verification are separate. Lack of hardware evidence beyond SM89 limits verification claims, not code generation: implement semantics for other architectures whenever the machine description and available evidence make the behavior reasonable, using conservative selector guards and fallback paths for unresolved forms. Record hardware verification by architecture and tested forms rather than gating native generation to SM89.
- Every fallback (opaque or primitive) of a class with an md `BRANCH_TYPE` keeps its control flow (`Builder.flow`): direct targets (RSImm relative, UImm absolute) and returns use `taken = call(...); if (taken == 0) goto <untaken>; goto/call/return`, indirect targets use `dest = call(...); goto/call [dest]`. Tier B had silently dropped this (only native BRA/CALL/RET/EXIT branched), and SM90+ spell BRA defaults `nocond__div_conv`/`nodepth_bra`, so every SM90+ BRA was opaque without a goto. Guards on default selectors use the md default (`operations.default`). The layer-3 dataflow test also checks Ghidra's flow type against `BRANCH_TYPE` per class.
- `python -m tools.semantic_census SMxx...` ranks classes in the real corpus by static occurrence and native/primitive/opaque status (selector guards only; ~30 s per arch on 32 cores).
- Opaque ABI is `(inputs...)`: registers and decoded immediates in operand order; no raw word (nothing consumed it; the bytes are at the call's address) and no SM (comes from the language id). Primitive ABI is `(class ordinal, decoded values...)`; every primitive class has a single span variant, and the runtime rejects one that doesn't. Multiple destinations return one byte bundle, preventing duplicate stateful calls and preserving overlapping source/destination values.
- `tests/ghidra_emulate.py` executes actual p-code with Ghidra's `PcodeEmulator`; `tests/cases/*` cover values, memory, predicates, branches, execution limits, and strict fallbacks (layer 4). The scalar GPU fixtures (`tests/harness/scalar.py`) compare whole SM89 kernels through EXIT against the GPU via ctypes CUDA Driver API. All 7,680 output comparisons passed (128 per kernel; FSEL/FMNMX checked bit-exactly; other floating NaN payload/sign differences normalized). Device access works outside the sandbox. Architecture-wide hardware coverage remains incomplete.
- Complete SLEIGH generation/compilation before parallel language loading. Ghidra auto-compiles stale specs, and concurrent compilers writing one `.sla` can corrupt it.
- Run language builds and GPU validation outside the sandbox. The user explicitly requested this; Ghidra's JDK/config setup and GPU/device access may fail inside the sandbox.
- Native selector checks are decode-time constraints, with separate opaque constructors. Encoded scalars use anchored constructor actions (`inst_start * 0 + expression`): unanchored computed exports crash Ghidra 12.1's native compiler. Register-view aliases avoid redundant snapshots; multi-output calculations capture inputs before writes.
- Expressions over constants and plain immediate fields are computed while decoding (`sem_sleigh.Fold`: a constructor action exports the constant; comparisons and `ite` are carries of masked sums, at most 32 bits), so the HFMA2.MMA constant move is one COPY. Unused operand values and unreachable subtables are omitted; `sass.build_languages` rejects unused-temporary diagnostics.
- Compact p-code regression fixtures assert one operation for immediate/register MOV, two for ordinary IMAD/IADD3 and three for LOP3 XOR with discarded predicate output. Dataflow checks still require exact reads/writes, adjusted for unused boolean/constant-comparison inputs and byte-width store sources; opaque fallbacks retain full md reads.

- FP64 DADD/DMUL/DFMA are native for RN with pair/uniform/immediate/constant operands and absolute/negate flags. DSETP shares ordered/unordered comparison logic, including complementary predicates and AND/OR/XOR. Directed rounding and DSETP MIN/MAX stay opaque. DFMA uses binary128: exact product, rare possible double rounding on the sum/narrowing. FP64 has the same Ghidra minimum-subnormal underflow band exclusion. SM89 hardware fixtures cover all four families.

- Packed FP16 HADD2/HFMA2 support H1_H0/H0_H0/H1_H1, per-half absolute/negate, SAT, packed register/uniform/constant inputs and separate immediate lanes (high first in FORMAT). HFMA2 widens to binary128 for an exact finite product/sum and narrows once; HADD2 widens to fp64; HMUL2 multiplies natively. Low-half broadcasts read only two bytes in native p-code, with or without |x|/-x (applied to the half). Families (`sass/families/floating.py`, 2026-10-13): HADD2/HFMA2 F16_V2 (exact: FTZ/FMZ opaque; readable ignores them, also on SM100+ `hfma2_mma` classes), HADD2.F32 with FTZ/SAT, HMUL2 with FTZ/FMZ/SAT, HMNMX2 F16/BF16/E6M9 with .NAN/.XORSIGN/F16 FTZ/.IS_A. Swizzles and HMNMX2's per-format NaN test/order are `select_lookup` values (forking on them made SM90 18.75 MB). BF16/E6M9 arithmetic formats, F32/H0_NH1 inputs and RELU stay opaque. HFMA2.MMA is native only for `-RZ, RZ, immediate` with nofmz/nosat: it preserves zeros/infinities/denormals but maps each NaN to 0x7fff (SM89 hardware). Decode-time canonicalization keeps it one COPY. Seven GPU fixtures patch only an arithmetic word for lane/modifier/MMA testing, then execute the same cubin on GPU and emulator.

- Step 2 adds mixed `URb`/`URc` inputs, uniform opcode aliases, native PRMT (all seven modes), FSEL and ordinary FMNMX. FMNMX numeric inputs win over NaN, two NaNs return `0x7fffffff`, and signed zeros choose -0 for min/+0 for max. `.NAN`, `.XORSIGN`, predicate-result `.IS_A`, packed/saturating VIADD and its carry modes stay opaque. Hardware coverage includes SM89 FSEL and FMNMX/FTZ; FSEL.FTZ remains emulator-tested. All nine architectures pass value/dataflow tests; rejected class selectors are reported as opaque in coverage.

- IMAD.HI selects the high word of the full 64-bit product plus 64-bit addend, including low-word carry; CUDA mad.hi lowering supplies the addend in the high register of a pair. SM75/80 HI/WIDE constant forms declare 32-bit C sources and remain opaque pending extension evidence. Wide views containing a hardwired zero slot are also explicit fallbacks, except views starting at RZ/URZ, which retain all-zero semantics.

## GPU semantics oracle (Phase 5)
- `pytest tests -m gpu --require-gpu` compiles the SM89 fixture kernels, verifies target mnemonics are executed, runs the GPU via ctypes CUDA Driver API, and compares whole-kernel Ghidra `PcodeEmulator` outputs for 128 random/edge vectors each.
- `sass/cubin.py::kernel_image` reads actual text, constant sections and CUDA parameter metadata. The harness seeds bank 0 launch dimensions, metadata-defined pointers, and named TID/CTAID registers. It runs independent threads from entry to EXIT, with PC bounds and an instruction budget. GPU access works outside the sandbox.
- Cooperative fixtures (`Fixture(cooperative=True, block=N)`, `tests/cases/threads.py`, kernels `tests/kernels/threads_semantics.cu`) emulate each block as one: `tests/BlockEmulator.java` (compiled by `ghidra_emulate.block_emulator` into `.cache/java/`, loaded beside Ghidra's classes) is a `PcodeEmulator` whose threads share every space except `localmem` (Ghidra keeps only register/unique thread-local). Warps take turns; a turn steps the live lanes at the warp's lowest PC together (the active mask, guard-predicated lanes excluded), SHFL/VOTE first gather each lane's operand (`WARP_INPUTS`) into the runtime warp context, and `bar__SYNC*` holds a thread until every live thread of the block arrives (barrier ids and counts unmodelled). Blocks run one after another (no inter-block communication); min-PC reconvergence is not the hardware scheduler. Don't add a `tests/java/` directory: on `sys.path` it shadows JPype's `java` package.
- Hardware-established SM89 behavior: PRMT SASS source order is data A, selector, data B. F2I.TRUNC.NTZ to S32 returns 0 for NaNs and clamps infinities/finite overflow. Other NTZ formats/modes remain unsupported. Implicit memory descriptor forms use ordinary global/local pointers; explicit descriptors remain opaque. Shared-memory X4 addressing scales the base register without changing its value.
- More SM89 hardware facts (2026-10-13, GPU fixtures in `tests/cases/conversions.py`, `fp32.py`, `predicates.py`):
  - FCHK.DIVIDE Pu, a, b depends only on the biased exponents: `ea <= 24 or ea == 255 or eb <= 1 or eb >= 252 or ea - eb >= 127 or eb - ea >= 125` (signs, mantissas and |x|/-x ignored; 0 mismatches on 1.1M pairs incl. every boundary cell).
  - F2I saturates in every mode; a NaN gives 0 with .NTZ (ptxas emits it for 32-bit destinations from F32/F16) and the destination's top bit otherwise (0x80000000, 0x8000000000000000, also for U64). .FTZ flushes a denormal input (CEIL of +denormal: 1 without, 0 with).
  - FRND rounds to an integral value keeping a zero's sign; an F32 NaN gives 0x7fffffff, an F64 NaN keeps its payload, quieted. F2F keeps a NaN's sign and payload (aligned to the top of the fraction), quieted. I2F is exactly rounded in all four modes; an F16 result is zero-extended in Rd.
  - PLOP3 with Pu == Pv writes Pu's value.
- Floating comparisons are exact except NaN payload/sign. MUFU approximation, device calls/returns, barrier reductions and divergent warps are not hardware-verified here. Hardware-verified multi-thread forms (2026-10-14, all lanes active): SHFL IDX/UP/DOWN/BFLY follow PTX shfl.sync exactly (524288 lane results with random b and c; UP's bound `(lane & seg) | (clamp & ~seg)` is a lower bound, the other modes check only `j <= bound`, so BFLY may leave the segment downward; b's bits above 4 and c's other bits are ignored), VOTE ANY/ALL/EQ and the ballot, and shared memory across BAR.SYNC between four warps. Scalar fixtures keep shared memory thread-private; BSSY/BSYNC are acknowledged for independent scalar loop execution.

- Native carry chains include IADD3.X (two predicate inputs), LEA LO/HI/SX32 with .X, and IMAD LO/HI/WIDE .X, including uniform aliases. IADD3 Pu/Pv are unary thresholds at 2^32/2^33; Pu wins aliased outputs. Ordinary negation preserves the 33-bit +1; .X uses complement plus predicate inputs. LEA selects its shifted low/high word before modifiers. IMAD HI/WIDE carry reports unsigned overflow of the full 64-bit product-plus-addend. Ra/Rb cannot both be modified for IADD3/LEA. The carry GPU fixtures (`tests/cases/carry.py`) check patched whole kernels against independent integer references and actual Ghidra p-code; SM89 evidence does not establish other architectures on hardware.

## Exact and readable floating point (2026-10-08)
- Two languages per architecture: `smXX` is exact (hardware results), `smXX_readable` is the plain formula. `Gen(arch, fp)`, `gen_sleigh.variant(arch, fp)`, `--fp=` on `gen_sleigh`/`build_languages` (builds both by default). The ELF opinion lists only the exact languages. Decode, display and dataflow are identical, and every Ghidra test takes the lowering (`pytest -m ghidra --fp readable|all`, `python -m tests.semantics ARCH readable`, `compare_ghidra_disassembly --fp readable`).
- `sass/sem_sleigh.py` (`Lower.float_op`) contains both lowerings; `gen_sleigh.MODES` names them. The readable lowering uses native-width `f+`/`f*` and ignores rnd, FTZ/FMZ, fusion and FMNMX NaN/±0 rules (including .NAN). SAT and abs/neg remain. Its reference is the unfused RN softfloat formula, compared bit for bit.
- Exact directed rounding (fp32 via fp64, fp64 via binary128) uses s = RN_wide, a TwoSum residual (zero for products, which are exact in the wide format), RN narrowing, then ±1 on the encoding by residual sign. RM zero-sign fix: an exact cancellation is -0 unless both addends are +0. This also cancels the emulator's minimum-subnormal underflow error. SM89 GPU fixtures cover .RZ/.RM/.RP for FADD/FMUL/FFMA/DADD/DMUL/DFMA. Ghidra 12.1.4 binary128 `f<` orders NaN operands, so the code guards with `nan()`.
- Treat IEEE rounding as shared floating-point machinery, not an F2FP-only feature: the exact-rounding strategy can apply to arithmetic operations such as FADD/FMUL/FFMA as well as conversions. Reuse or factor the rounding implementation where appropriate, while preserving each operation's rules for fusion, FTZ/FMZ, signed zero, saturation, and exceptional values.
