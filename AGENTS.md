# nvdisasm reverse engineering

Target: `nvdisasm` from CUDA 13.4 (V13.4.92, built 2026-09-01), stripped x86-64 PIE.
Local copy used so far: `/tmp/.venv/lib/python3.13/site-packages/nvidia/cu13/bin/nvdisasm`.
All addresses below are specific to that build.

## Tooling
- Ghidra via GhidraMCP. GUI server was at `http://127.0.0.1:33363/` (`set_ghidra_server`). Image base 0x100000, so Ghidra addr = file/objdump addr + 0x100000.
- GhidraMCP lookups need exact function entry addresses; inner addresses return "No function".
- `uv run extract_md.py <nvdisasm>` dumps the embedded machine descriptions to `out/raw/` (gitignored, monolithic). `python3 build_out.py` lays them out as `out/SMxx/{latencies,patterns}.txt`, `out/SMxx/md/{_NN_SECTION,OPCODE}.txt` and `out/SMxx/semantics/OPCODE.json` (committed).

## Findings
- Opcode/operand name strings are ROT13 (`rot13_decode` 0x168cb0); `strings` won't find them. Mnemonics are matched by prefix (`str_after_prefix` 0x11831b).
- Diagnostics: `diag_report` 0x111b70 (variadic). Messages are 16-byte `diag_msg {severity, suppressed, fmt}` records reached via a pointer slot: code -> slot -> record -> fmt.
- Branch-stack pass (pre-Volta SSY/PBK/PCNT/PRET/... stack), driver `bstack_analyze_function` 0x1da320: entry frame per block, one ordered pass over CFG edges (`bstack_propagate_edge`), then join/exit checks and pop-target resolution (`resolve_branch_target` 0x1d11b0, emits `TARGET=` annotations). Push/pop kind pairs: 1 RET/PRET, 2 SYNC/SSY, 3 BRK/PBK, 4 CONT/PCNT, 5 LONGJMP/PLONGJMP, 7 EXIT/PEXIT.
- Machine descriptions: per arch (SM75 80 86 89 90 100 101 103 120) three blobs in `.data` — md, latencies, patterns — registered by `md_register_embedded_blob` 0x1be200, loaded by `md_load_blob` 0x1beb30.
  - Cipher `mdcipher_decrypt` 0x173030: glibc-LCG keystream (4 bytes/step) + inverse sbox at 0x1fa5e0, ciphertext-chained, seeded by a 16-bit per-arch key.
  - md blobs are then LZ4 stream-compressed chunks `{u32 raw, u32 comp, data}` with 64 KB dictionary; latencies/patterns are encrypted only.
  - External override files `md_SMxx` / `latencies_SMxx` / `patterns_SMxx` are supported (`md_register_override_file` 0x1be3f0); a `_` suffix means key 0 (plaintext) — untested.
- Semantics model: md gives per-CLASS FORMAT (operand names), CONDITIONS, PROPERTIES (INSTRUCTION_TYPE...), PREDICATES (IDEST_SIZE/ISRC_*_SIZE in bits), OPCODES, ENCODING. latencies gives connectors (Ra/Rb/Rc/Re read, Rd/Rd2 written; URx, Px analogues), TABLE_TRUE/OUTPUT/ANTI latencies and OPERATION SETS (pipes). Register span = ceil(SIZE/32). No functional (value) semantics exist.

## Decoding (sass/, tests/)
- `mdlib.py` parses md classes/enums/tables; `sass/ir.py` builds per-class decode IR; `sass/pydecode.py` is a reference decoder; `tests/compare.py ARCH real|synthetic|mutated [N]` diffs it against nvdisasm (`tests/oracle.py`, sqlite cache in `.cache/`). Real corpus = `.text.*` of cubins extracted by cuobjdump from `/usr/local/cuda/lib64` libs.
- Oracle: `nvdisasm -b SMxx raw.bin` decodes raw 128-bit words (~70k/s). One illegal word fails the batch (rc=1, empty stdout) but stderr lists every bad address; drop and rerun. Branch targets are absolute, so results depend on the word's address in the batch (recorded). Ambiguous encodings can abort with `nvdisasm fatal : More than one pattern matched ... at address` (also parsed). Some decodable words print as blank (JSON shows `opcode:""`): names like GATHER/SCATTER/`__HIR*`/PAUSE/E6M9 — cause not found, treated as status `blank`.
- Matching: opcode (`BITS_13_91_91_11_0`, ranges concatenated MSB first) + literal `=N` fields; `=*N` and unlisted bits are ignored. `=*X` operands (and the arguments of starred tables `=*T(a,b)`, which still decode) must hold a valid enum value or the class does not match (this separates classes sharing an opcode, e.g. NonZeroRegister vs ZeroRegister); plain `=X` operands out of their enum print `???N`. Tables decode by inverse lookup (first row wins; no row = illegal). Multi-field `ConstBankAddress2` stores offset/4, `IDENTICAL(a,b)` puts one field in both.
- ALTERNATE classes are assembler syntax and never printed, except pseudo classes whose `FORMAT_ALIAS` table (`GetPseudoOp*` in TABLES, `-` wildcard, first match) is non-zero and whose `$(...)$` scheduling operands are valid enum values (IMAD.MOV/SHL/IADD). md bug: GetPseudoOpRIR lists 32768 twice and lacks 65536, so 0x10000 is never SHL.
- md ambiguity: two non-ALTERNATE classes matching one word makes nvdisasm abort (`More than one pattern matched`, e.g. SM75 ald_PHYS_ vs ald__PATCH_*); pydecode treats it as illegal too.
- Tests: `uv run --with pytest python -m pytest tests -k pydecode` ratchets per-class pass/fail against `tests/baseline/SMxx.json` (`--update-baseline` to accept, `--full` for the whole real corpus).
- Printing: for a value with several enum names the last *definition* wins (PT over P7, "64" over "_64", explicit `SR138=138` over the earlier `SR_CgaLinearMemorySlot`); defaults compared by value and omitted (`UImm(n/d*)` and `/PRINT` always print); `e_desc` (bit 101) off hides `desc[URx]`; floats `%.20e` if |x|>=1e9 else `%.20g`, `+INF`/`-QNAN`/`+SNAN`/`-0.0` with a trailing space (`+QNAN .H1`); a default operand that carries a modifier still prints (`[RZ.X8+UR4]`); flags `-|..|` wrap an operand plus directly following modifiers but not those after a `{/REUSE}` group; a `c[..][..]` bank followed by a modifier prints as `c[b] [o].MOD`; adjacent operands without a literal are space-separated (`RET.REL R2 -0x1240`).

## SLEIGH (processor/SASS, sass/gen_sleigh.py)
- `python3 -m sass.gen_sleigh SM89 ...` writes `processor/SASS/data/languages/sass_smXX.slaspec` + `sass.ldefs` (ids `SASS:LE:64:smXX`); `sass_common.sinc`, `.pspec`, `.cspec` are hand-written. Ghidra recompiles a stale `.sla` on load; `support/sleigh` compiles standalone (~5 s/arch).
- `tests/ghidra_decode.py` (run with Ghidra's pyghidra venv) loads a language straight from the `.ldefs` via the package-private `SleighLanguageProvider(ResourceFile)` constructor (reflection) -- no install. `tests/compare_ghidra.py ARCH real|synthetic|mutated` diffs it against pydecode with `FLOAT_HEX` (SLEIGH can't print floats); guard shown as `@P0:` (SLEIGH drops the space before a mnemonic) and operand whitespace ignored.
- Don't name a repo dir `ghidra/`: from the repo root Python treats it as a namespace package shadowing pyghidra's Java `ghidra` package (RecursionError).
- SLEIGH facts that shaped the generator: fields joined with `&` must be in one token, so every pattern is `(lo ; hi)` and patterns combine with `&`; subtable coverage is not folded into the parent's pattern (a subtable with no matching constructor makes the instruction fail, no fallback), so class discrimination is all in root constraints; overlaps are lenient (first in file order) unless nested; an operand may not be defined in several OR branches; a field can't be constrained and displayed in one pattern (separate aliases); `!=`/`<` on wide fields splits into huge state sets (16-bit `!=0` hung the compiler at 25 GB). Membership constraints now use aligned positive bit blocks. Pseudo-op scheduling validity uses a first-in-order blocker constructor.
- Ghidra silently truncates decompressed `.sla` data at 16 MiB (`SlaFormat.MAX_FILE_SIZE` / `LinkedByteBuffer.ingestStream`), causing random "Format violation" errors. Earlier large-OR failures were size failures. Shared display fields and per-class semantic span subtables keep all nine languages under the cap (largest current build: SM90, 7,527,015 bytes). Class span tables enumerate only output (and native/primitive) spans; read-only expression-sized inputs of opaque classes get per-operand subtables zero-extended to their widest view (SLEIGH requires one export size per subtable; >256 bytes uses `DYN_<operand>_<n>` registers). Enumerating all spans jointly made TEX tables 432 rows.
- Register dataflow p-code: md register reads/writes via opaque pcodeops, instruction guards, and branch/call/return. Modifier spans are evaluated by `sass/mdexpr.py`, exactly (including 0, 3, and matrix spans above 8), without a widest-span fallback. Immediate operands with misleading latency resources (IPA `attr`) are excluded by operand type. Register-bank overflow uses sinks to preserve display decoding; its dataflow is undefined. Wide zero constants use `zext`; above SLEIGH's 256-byte temporary cap, initialized internal ZERO registers are used.
- `SASS_SLEIGH_OUT=/tmp/...` redirects generation and Ghidra tests; copy the shared `.sinc`, `.pspec`, and `.cspec` there first. `tests/test_dataflow.py ARCH [N]` compares structured Ghidra p-code against decoded md operand roles/spans. `SASS_DATAFLOW=1` enables its pytest integration. `compare_ghidra.py` compares standalone 64-bit immediates in MOV.64/UMOV.64/MOV64IUR modulo 2^64 because SLEIGH prints computed values as signed int64.

## Operand values and instruction semantics (2026-10-07)
- `sass/semantic.py` preserves exact register effects for all classes, and materializes typed immediate/table/modifier/constant-bank values for supported operations. CX/descriptors/attribute/stateful operands require an explicit `sass_operand_value` provider.
- `sass/operations.py` registers the 51 operation families across all nine architectures. Supported class/selector combinations use native p-code or `sass_prim_*`; unknown conventions remain opaque. LEA HI/extended, carry/predicate conventions, SM120 extra IMNMX predicates, descriptor/extended memory, and branch-stack CALL/RET modes are explicit fallbacks.
- FADD/FMUL/FFMA/FSETP are native p-code for RN with .FTZ/.SAT/FMUL scale; only .RM/.RP/.RZ and .FMZ use `sass_prim_*` (`dispatch(b,'prim')`). FFMA is `float2float(fp64 a*b + c)`: double rounding, rare 1-ulp differences, chosen for readability. Ghidra 12.1.4's emulator rounds results in (2^-150, 2^-149) to zero instead of 2^-149 (`FloatFormat.getEncoding` `n < 0` branch); tests exclude that band.
- `sass/runtime.py` (test-only; Ghidra never loads it) supplies strict CPU primitives; `sass/softfloat.py` uses exact rational IEEE rounding. MUFU requires a hardware-specific handler. Warp operations use explicit 32-lane context; synchronization events require acknowledgement and do not implement a scheduler. Barrier reductions require a handler.
- Special registers are a register file at offset 0x3000 named from the md `SpecialRegister` enum (`SR_CTAID.X`; `_64` views for CS2R.64); S2R/CS2R are plain copies and SRZ reads 0. Emulation seeds them by name like any register; unseeded ones read 0.
- Spaces: `ram`, `cbank` (bank << 32 | uint32(offset)), `shared`, `localmem`. The identifier `local` is reserved in SLEIGH. The Phase 5 test harness reads parameter offsets from cubin PARAM_CBANK/KPARAM_INFO records; these SM89 pointer kernels use bank 0 base 0x160. The general loader/compiler prototype remains Phase 6 work.
- Detailed per-class coverage manifests are generated beside each `.sla`; committed `processor/SASS/semantics/coverage.json` summarizes all architectures. Native status records a candidate override with selector guards, not all-encoding coverage.
- Every fallback (opaque or primitive) of a class with an md `BRANCH_TYPE` keeps its control flow (`Builder.flow`): direct targets (RSImm relative, UImm absolute) and returns use `taken = call(...); if (taken == 0) goto <untaken>; goto/call/return`, indirect targets use `dest = call(...); goto/call [dest]`. Tier B had silently dropped this (only native BRA/CALL/RET/EXIT branched), and SM90+ spell BRA defaults `nocond__div_conv`/`nodepth_bra`, so every SM90+ BRA was opaque without a goto. Guards on default selectors use the md default (`operations.default`). `tests/test_dataflow.py` now also checks Ghidra's flow type against `BRANCH_TYPE` per class.
- `tests/semantic_census.py SMxx...` ranks classes in the real corpus by static occurrence and native/primitive/opaque status (selector guards only; ~30 s per arch on 32 cores).
- Opaque ABI is `(inputs...)`: registers and decoded immediates in operand order; no raw word (nothing consumed it; the bytes are at the call's address) and no SM (comes from the language id). Primitive ABI is `(class ordinal, decoded values...)`; every primitive class has a single span variant, and the runtime rejects one that doesn't. Multiple destinations return one byte bundle, preventing duplicate stateful calls and preserving overlapping source/destination values.
- `tests/ghidra_emulate.py` executes actual p-code with Ghidra's `PcodeEmulator`; `tests/test_semantics.py` covers values, memory, predicates, branches, execution limits, and strict fallbacks. `tests/gpu_semantics.py` compares 28 whole SM89 kernels through EXIT against the GPU via ctypes CUDA Driver API. All 3,584 output comparisons passed (128 per kernel; FSEL/FMNMX checked bit-exactly; other floating NaN payload/sign differences normalized). Device access works outside the sandbox. Architecture-wide hardware coverage remains incomplete.
- Complete SLEIGH generation/compilation before parallel language loading. Ghidra auto-compiles stale specs, and concurrent compilers writing one `.sla` can corrupt it.
- Native selector checks are decode-time constraints, with separate opaque constructors. Encoded scalars use anchored constructor actions (`inst_start * 0 + expression`): unanchored computed exports crash Ghidra 12.1's native compiler. Register-view aliases avoid redundant snapshots; multi-output calculations capture inputs before writes.
- `sass/operations.py` simplifies LOP3 truth tables and selects signedness, comparisons, shift modes, modifiers and memory widths in value subtables. Compound callbacks receive only children before the next FORMAT comma. Unused operand values and unreachable subtables are omitted; `sass.build_languages` rejects unused-temporary diagnostics.
- Compact p-code regression fixtures assert one operation for immediate/register MOV, two for ordinary IMAD/IADD3 and three for LOP3 XOR with discarded predicate output. Dataflow checks still require exact reads/writes, adjusted for unused boolean/constant-comparison inputs and byte-width store sources; opaque fallbacks retain full md reads.

- Step 2 adds mixed `URb`/`URc` inputs, uniform opcode aliases, native PRMT (all seven modes), FSEL and ordinary FMNMX. FMNMX numeric inputs win over NaN, two NaNs return `0x7fffffff`, and signed zeros choose -0 for min/+0 for max. `.NAN`, `.XORSIGN`, predicate-result `.IS_A`, packed/saturating VIADD and carry modes stay opaque. Hardware coverage includes SM89 FSEL and FMNMX/FTZ; FSEL.FTZ remains emulator-tested. All nine architectures pass value/dataflow tests; rejected class selectors are reported as opaque in coverage.

- IMAD.HI selects the high word of the full 64-bit product plus 64-bit addend, including low-word carry; CUDA mad.hi lowering supplies the addend in the high register of a pair. SM75/80 HI/WIDE constant forms declare 32-bit C sources and remain opaque pending extension evidence. Wide views containing a hardwired zero slot are also explicit fallbacks, except views starting at RZ/URZ, which retain all-zero semantics.

## GPU semantics oracle (Phase 5)
- `tests/gpu_semantics.py --require-gpu` compiles 28 SM89 kernels, verifies target mnemonics are present and executed, runs the GPU via ctypes CUDA Driver API, and compares whole-kernel Ghidra `PcodeEmulator` outputs for 128 random/edge vectors each (3,584 comparisons). `--compile-only` validates compiler output; `SASS_GPU=1` enables the pytest hardware wrapper.
- `sass/cubin.py::kernel_image` reads actual text, constant sections and CUDA parameter metadata. The harness seeds bank 0 launch dimensions, metadata-defined pointers, and named TID/CTAID registers. It runs independent threads from entry to EXIT, with PC bounds and an instruction budget. GPU access works outside the sandbox.
- Hardware-established SM89 behavior: PRMT SASS source order is data A, selector, data B. F2I.TRUNC.NTZ to S32 returns 0 for NaNs and clamps infinities/finite overflow. Other NTZ formats/modes remain unsupported. Implicit memory descriptor forms use ordinary global/local pointers; explicit descriptors remain opaque. Shared-memory X4 addressing scales the base register without changing its value.
- Floating comparisons are exact except NaN payload/sign. Warp collectives, MUFU approximation, device calls/returns, barrier reductions and cross-thread concurrency are not hardware-verified here. Shared-memory cells are thread-private; BSSY/BSYNC are acknowledged for independent scalar loop execution.
