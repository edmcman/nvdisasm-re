SASS semantic coverage

How much of each architecture’s instruction set the generated Ghidra languages give semantics. A cell shows two counts for an opcode: C, covered classes / machine-description classes, and below it M, covered modifier combinations / modifier combinations, a combination being one complete instruction form such as FADD.FTZ.RZ. Covered means it has semantics; a+b/n means a are fully covered and b partly covered, out of n. Category rows count opcodes with any semantics. Categories follow NVIDIA’s SASS reference.

The strip along a cell’s bottom edge splits its classes by status. A cell’s tooltip and details say how what has semantics is verified, each class or combination counted once by its strongest evidence. A combination counts as verified only when a test ran exactly it (evidence.json), so testing FTZ and RZ separately does not make FTZ+RZ tested. Evidence, strongest first:

Class names end in their operand forms: R register, U uniform register, I immediate (sI signed), C constant c[bank][addr], Cx constant in a bank chosen by a uniform register. An operand flag is written operand@flag, e.g. Ra@negate (−Ra), set or unset. A cell’s colour goes from red (no class has semantics) to green (all do).
