SASS semantic coverage

How much of each architecture’s instruction set the generated Ghidra languages give semantics. A cell shows classes with semantics / machine-description classes for an opcode; its bottom edge shows the split by status. Category rows count opcodes with any semantics. Categories follow NVIDIA’s SASS reference.

native
P-code computes the result, so Ghidra’s decompiler and emulator see the real operation.
primitive
Calls a named runtime operation (sass_prim_*) that our emulator executes; the decompiler sees only a call.
opaque
Calls a generic operation with the machine description’s reads and writes but no semantics: dataflow only.

Marks in a cell say how its classes with semantics are verified (per class in evidence.json):

Ggpu
an SM89 GPU fixture that passed on hardware, exactly as committed, checks it: the instruction is on the fixture kernel’s path from the test inputs to the compared output.
Pptxas
ptxas emits it for an annotated PTX probe in tests/ptx: evidence of the lowering, not of values.
Rreference
emulator cases check it against an independent reference in tests/refs.

Classes with semantics are native or primitive. A cell’s colour goes from red when none of its classes have semantics to green when all do. Generated by sass-refresh-coverage; hover a cell for exact counts, click an architecture to show only its opcodes.
