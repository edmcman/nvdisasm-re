Constraint rules

The analyzer starts with unknown argument types and relationships obtained from individual instructions. It propagates those relationships through branches and loops, then describes the bounded array accesses. Below, i, j, c are integer indices or counters; M, N, s are symbolic values that stay unchanged during a loop. They need not be literal constants. These rules use the conditional integer interpretation described above; they do not by themselves prove that machine arithmetic cannot overflow.

1. Connect loads to the operations that consume their values

A load from a pointer gives an initially unknown element type, written α. Consumers constrain that type. Type unification means making connected types agree.

x = load(p)       ⇒ p : pointer(global, α), x : α
y = fadd.f32(x, z) ⇒ x, y, z : f32
Together          ⇒ p : pointer(global, f32)

Copying or merging a value connects its type to the incoming values. This establishes argument roles and element types; it does not yet establish tensor dimensions.

2. Separate an address base from its integer offset

When addition combines a pointer and an integer offset, the result remains a pointer to the same element type. For a four-byte access, divide the byte offset by four to obtain an element index.

p : pointer(global, α), offset : integer
address = p + offset ⇒ address : pointer(global, α)
address = p + 4*i    ⇒ element index = i

An integer address calculation alone does not supply an array extent. Bounds on its index are still required.

3. Apply assignments simultaneously

Each definition has its own identity, even when the machine reuses a register. This is static single assignment, or SSA. At a control-flow edge, substitute all incoming definitions together.

Before: i + remaining = N
Update: i′ = i + 3, remaining′ = remaining - 3
After:  i′ + remaining′ = N

The same substitution tracks an address advancing by a symbolic stride: address′ = address + 12*M preserves address = base + 4*M*i when i′ = i + 3. No countdown-loop recognizer supplies that equation.

4. Restrict each branch using its comparison

Instructions reached only when a condition holds inherit that condition. A strict integer comparison becomes an inequality with a one-unit gap.

i < N       ⇒ i - N ≤ -1
0 ≤ i < N   ⇒ i ≥ 0 and i - N ≤ -1
j ≤ 7       ⇒ j < 8
i < N and i ≥ N ⇒ unreachable path

Unsigned order comparisons also bound their operands between zero and the largest value of their word width. Signed comparisons use the signed interpretation. Thread and block index limits come from the stated SM90 launch conventions and explicit input ranges, not from a guessed tensor shape.

5. Keep assignments controlled by the same condition together

Split on the condition, apply all assignments for that outcome, then combine the outcomes. This retains relationships that separate intervals would lose.

if condition: y = x+1; z = 11-x
else:         y = x;   z = 12-x
Either way:   y+z = 12

6. At a merge, retain only facts covering every incoming path

The analyzer keeps equalities common to the paths. For each tracked inequality expression, it keeps an upper bound large enough to cover both paths. Combining incoming paths this way is called a join.

Path A: x ≤ 3     Path B: x ≤ 7
Merged: x ≤ 7

Path A: x=2, y=8  Path B: x=7, y=3
Merged: x+y=10; individual values are unknown

7. Retain products needed for symbolic strides

A symbolic stride requires relationships involving products, such as M*i. The analyzer tracks a finite set of these polynomial expressions. Equality propagation uses their algebraic relationships; linear inequality solving bounds the tracked expressions.

x = y             ⇒ M*x = M*y
x ≤ y and M ≥ 0   ⇒ M*x ≤ M*y
x ≤ y and M < 0   ⇒ multiplying would reverse the inequality

The implementation multiplies inequalities only after establishing a nonnegative factor and only when the resulting products fit its tracked expressions. It does not assume a symbolic matrix stride is positive merely because it is named M.

8. Use integer bounds and cancel proven positive factors

An integer cannot lie strictly between two consecutive integers. A factor known to be positive can be cancelled without reversing an inequality.

integer x ≤ 7/2                ⇒ x ≤ 3
s*(c-h) < 0 and s > 0        ⇒ c < h
integer c, h and c < h         ⇒ c ≤ h-1

The loop-count implementation first tries to establish the product inequality using its existing polynomial expressions, then applies this cancellation and integer rounding. An unknown sign does not justify cancellation.

9. Preserve the meaning of word operations

For a nonnegative integer x, a low-bit mask splits it into a quotient and remainder. For example, keeping two bits gives:

r = x & 3; q = x >> 2
x = 4*q + r, q ≥ 0, 0 ≤ r ≤ 3
If 4 ≤ x ≤ 7: r = x-4

Complement and predicate extension have separate rules:

~x = -x-1 modulo 2^word_width
one-bit true                 = 1
zero-extend true to 32 bits   = 1
sign-extend true to 32 bits   = -1 as a signed integer

These distinctions prevent a predicate from silently switching between 1 and -1. Integer bounds on a normalized expression must also respect intermediate wrapping: (~d+n)+d equals n-1 modulo the word width, including when an intermediate value wraps.

10. Count loop iterations and verify that the result is preserved

For a loop with a dominating header—a loop entry that every path to its body passes through—the analyzer adds an auxiliary integer counter c. It is zero on entry and increases by one when execution returns to the header.

Loop entry: c = 0, i = start
Loop step:  c′ = c+1, i′ = i+4*s
Derived:    i = start+4*s*c

States are propagated until they stabilize. To make that process terminate, widening weakens bounds that keep growing: it uses the configured thresholds -1, 0, 1 when applicable, otherwise drops the bound. The final fixed-point check verifies that every successor state includes the result of another transfer. Failure to stabilize or verify is not reported as a successful dimension proof.

11. Carry numerical error through reciprocal-based division

The compiler can implement integer division using floating-point conversion, an approximate reciprocal, multiplication, and integer correction steps. The analysis constrains these operations individually. It does not replace an approximate reciprocal with exact division.

ε = 2^-23
Positive integer d converted to float f, rounding upward:
    d ≤ f ≤ d*(1+ε)
Approximate reciprocal of f:
    target = 1/f, with a bounded floating-point error
Unsigned multiply-high, for w-bit operands a and b:
    result = floor(a*b / 2^w)

The reciprocal model assumes the documented one-ulp accuracy applies to the SM90 operation; an ulp is the spacing between neighboring floating-point values. It uses conservative bounds around the exact reciprocal, tracks the compiler's adjustments to the float encoding, and bounds conversion back to an integer. For example, an estimate used for floor(10/3) must be close enough for the integer correction steps to reach 3.

Under the required input conditions, these operation constraints establish the corrected quotient relationship q*s ≤ numerator < (q+1)*s. A possibly zero divisor, unsupported rounding mode, exceptional floating-point range, or solver timeout supplies no such fact. Some floor and modular relationships are relaxed over real numbers, which can lose precision; successful integer bounds are rounded only when justified.

12. Turn bounded element indices into dimensions

Separate a total element index into a quotient and remainder for an extent M, then require bounds for every access. Dimensions below follow physical element-stride order: the first coordinate advances by one element.

address = base + 4*(i + M*j)
0 ≤ i < M and 0 ≤ j < N
⇒ a sufficient access shape is A[M,N]

Candidate extents come from the program's comparisons, constant coordinate ranges, and launch limits. A coefficient used as a stride helps choose the decomposition. The analyzer also checks the whole current index against each extent, removes candidates known to be larger than another sufficient candidate, and prefers a kernel comparison when the remaining bounds are incomparable. For example, a surviving j ≤ 7 supplies extent 8 even when the launch-size expression is unrelated to that constant.

A dimension is complete only when the remaining quotient is zero and every coordinate is both nonnegative and below its extent for every access. Ambiguity, a missing bound, or an unsupported operation remains unresolved. A sufficient access shape does not uniquely identify the original source rank or the allocation's capacity.

Worked example: all four DOT reads stay below N

Let s > 0 be the stride and g the initial index. The corrected quotient q describes the iterations remaining:

q*s ≤ N-g-1 < (q+1)*s
r = (q+1) % 4; h = (q+1) // 4
q+1 = r+4*h

After the initial r scalar reads, let c count completed groups of four. The loop rules derive index = g+s*r+4*s*c. Combine the loop condition with the quotient bound:

index < N ≤ g+s*(q+1) = g+s*(r+4*h)
⇒ s*(c-h) < 0
⇒ c ≤ h-1
⇒ index+3*s ≤ g+s*(r+4*h-1) = g+s*q ≤ N-1

This bounds the last read in the group and therefore the preceding three. The loop condition index < N alone would bound only its first read. The equations are consequences of the common rules above, not a DOT-specific summary inserted into the analysis.

Implementation: type constraints and SSA, arithmetic and control flow, assignment and join, numerical constraints, and dimension decomposition. The implementation bounds the number and degree of tracked expressions; the mathematical implications above are not a claim of complete inference for arbitrary programs.
